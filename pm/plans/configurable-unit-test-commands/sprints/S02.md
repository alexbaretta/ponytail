# Sprint S02: Configure Governed Projects

Status: `IN_PROGRESS`

## Objective

Configure exact focused and full unit-test command families in each governed
consumer, prove focused selection, and complete the plan with one final
full-unit-test run per configured family.

## Dependencies

- Sprint S01 is `DONE`.
- Updated Ponytail skills are committed and installed.
- The user approved the complete plan and skill installation.
- Each repository's own instructions and active management artifacts are
  loaded before changing it.

## Questions

No open sprint-level questions. Exact command values are repository facts to
be discovered from authoritative scripts and package configuration.

## Feature F01: Configure One Governed Repository

Repeat this feature for IPG and GWEN as separate selective project
change-sets.

### [ ] Tasklet S02-F01-T01: Inventory Unit-Test Families

Trace each repository's unit-test entry points and runner selectors. Record
every independently owned language or runner family, its smallest reliable
focused command form, and its complete full-suite command.

Validation: each command is backed by an existing executable entry point; no
runner, wrapper, or conventional command is invented.

### [ ] Tasklet S02-F01-T02: Configure Focused And Full Commands

Add the named family table to the repository's canonical command inventory and
bind it from `AGENTS.md` if the existing reference is insufficient. Remove
superseded singular or duplicate command ownership.

Validation: configuration-contract checks pass and every family has exactly
one focused and one full command owner.

### [ ] Tasklet S02-F01-T03: Prove Focused Selection

Run representative individual test files or named test cases through every
configured focused command form. Do not run a package, workspace, language,
repository, or full unit-test suite.

Validation: every focused form selects only the requested tests and returns a
decisive result.

### [ ] Tasklet S02-F01-T04: Query Build Impact And Commit

Query only the intended configuration paths. Run reported build commands once
after final input edits; skip builds when no targets or indeterminate results
are reported. Commit the repository configuration selectively.

Validation: the commit contains only the consumer's unit-test configuration
and required management evidence.

## Feature F02: Complete Plan Acceptance

### [ ] Tasklet S02-F02-T01: Reconcile All Repositories

Confirm Ponytail, IPG, and GWEN each expose complete named unit-test-family
configuration and no portable skill contains a project-specific command.

Validation: configuration and project-neutrality tests pass.

### [ ] Tasklet S02-F02-T02: Run Final Full Unit-Test Commands

After every repository's final relevant edit and commit, run each configured
full unit-test command once in its owning repository. Do not substitute a
general CI command for a configured unit-test command, and do not rerun a
passing family without a later relevant edit.

Validation: every configured family has one recorded final result; failures
remain explicit and prevent plan completion.

### [ ] Tasklet S02-F02-T03: Run Remaining Final Acceptance

Run Ponytail's configured rule-copy, version, registry, generated-output, and
installer checks not already owned by its full unit-test command. Run only
other host-configured non-unit acceptance portions that apply to the changed
configuration.

Validation: all applicable final gates pass without an unconditional build.

### [ ] Tasklet S02-F02-T04: Install And Verify Ponytail

Install the committed Ponytail skill snapshot and run installer check mode.

Validation: installed skills match the committed sources and the installed
policy contains the configurable focused/full cadence.

### [ ] Tasklet S02-F02-T05: Close The Plan

Record exact commits, focused proof, final full-command results, build-impact
decisions, and installation evidence. Mark the sprint and plan `DONE` in a
selective management commit.

Validation: no child tasklet remains unfinished and all unrelated working-tree
changes remain excluded.

- Every full command runs once at final plan acceptance.
