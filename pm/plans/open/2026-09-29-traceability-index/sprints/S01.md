## Feature S01-F01: Versioned incremental projection

Acceptance: rebuildable PostgreSQL worktree generations contain the canonical
normalized traceability graph and reuse unchanged content and parse results
across worktrees.

### [ ] Tasklet S01-F01-T01: Version traceability inputs

Add immutable V1/latest-write V2 configuration readers, normalized entity and
relationship contracts, safe search-field policy, and boundary tests.

Implementation contract: split the existing configuration reader into frozen
physical V1 and V2 readers exported as `TraceabilityConfigReaders`. V1
normalizes to the current representation with the complete default safe search
field set. V2 adds the exact `index.searchableFields` array, accepts only
`entityId`, `entityKind`, `role`, `requirementId`, `path`, `unitName`,
`annotation`, and `description`, and rejects empty, duplicate, or unknown
values and keys. Migrate this repository's configuration to V2. Preserve the
existing relationship parser and reverse view byte-for-byte. Add exact reader,
normalization, malformed-input, and V1-compatibility cases to
`tests/requirements-traceability.test.js`; update the versioned-contract
manifest. Exclude PostgreSQL behavior and new prospective roles from this
tasklet.

### [ ] Tasklet S01-F01-T02: Provision the PostgreSQL index schema

Add the separately owned, versioned `ponytail_index` schema, roles, grants, and
idempotent setup integration in the existing configured database.

Implementation contract: `scripts/project-index.sql` owns immutable V1 tables
for projects, repository instances, worktrees, content identities, reusable
parse results, worktree/corpus generations, files, entities, relationships,
search documents, and published-generation pointers. Search documents own a
generated `tsvector` and GIN index. `scripts/setup-project-journal.sh` creates
the index owner/reader/writer roles, grants the configured runtime role writer
membership, applies the index SQL after the journal SQL, and registers the
project idempotently. Add the `pg` runtime dependency, package and structure
ownership, distribution checks, immutable-contract checks, and setup-stub
checks. Exclude runtime indexing logic.

### [ ] Tasklet S01-F01-T03: Implement incremental PostgreSQL generations

Create the projection component with exact content identities, shared parse
reuse, isolated worktree generations, transactional publication,
deletion/rename cleanup, `tsvector`/GIN search, bounded same-worktree writer
contention, rebuild, integrity, and recovery behavior.

Implementation contract: `src/project-index.js` resolves the configured
project UUID, canonical Git common directory, canonical worktree root, `HEAD`,
and dirty tracked content; hashes exact bytes and parser/configuration
identity; reuses immutable parse results; and publishes a complete
traceability generation in one transaction. It uses parameterized `pg`
queries, a non-blocking transaction advisory lock keyed by project,
repository, worktree, and corpus, and never stores arbitrary file bodies.
`tests/project-index.test.js` owns deterministic unit coverage with a boundary
client; `scripts/test-project-index-postgres.sh` owns real PostgreSQL setup,
same-worktree contention, cross-worktree isolation and reuse, rollback,
rebuild-equivalence, and cleanup. Exclude user-facing CLI dispatch.

### [ ] Tasklet S01-F01-T04: Validate projection acceptance

Run focused schema, parser, versioned-contract, incremental Git,
cross-worktree concurrency and isolation, security, and rebuild-equivalence
checks and record evidence.
