## Objective

Replace the six-coordinate certificate controller with integrated `(R,A,T,I)`
assessment, minimal campaign acceptance and agreed operational monitoring. Use
Q3-Q5 contracts; no replacement swarm registry, host API or generic scheduler.

## Draft work packages

1. Derive unresolved-object sets and the vector from the canonical scoped graph
   and admissible adequacy/review state. Distinguish unknown from complete,
   reviewed decomposition from nonempty links, and QA gates from graph counts.
2. Assess candidate productive descent, discoveries/invalidations and authorized
   scope amendments. Require actual passing test/implementation proof for T/I
   decrements. Compare the latest integrated scope, not summed worker claims.
3. Implement mechanical fast-forward acceptance of an exact reviewed/tagged
   candidate with a current base check. Concurrent submissions cannot overwrite
   each other. Return stale branches to the worker; do not rebase or repair them
   in the coordinator or reuse a verdict for a different candidate.
   After each accepted merge request, display the campaign completeness vector
   to the user, computed from the resulting integrated revision in `(R,A,T,I)`
   order. Cover native fast-forward acceptance as well as any hosted requests.
4. Implement the approved minimal project-scoped observations and assignment
   restart/conflict protection. Record no repeated source snapshots or full
   evidence payloads. Use existing local DB resources only if Q3 selects them.
5. Implement the resolved monitoring window/alert and truthful disturbance/scope
   treatment; suppress repeated unchanged alerts. Campaign completion requires
   zero graph gaps, required review, and fresh passing full QA on the candidate.

## Owning surfaces and proof

Reconcile `src/rolling-campaign.ts`, `src/rolling-operations.ts`,
`src/rolling-campaign-store.ts`, worker-submission/review/integration/publication
components, obligation scripts, `src/rolling-cli-registry.ts`, SQL and MCP
adapters. Keep only conforming capabilities; retain bounded historical readers.

Focused tests use existing obligations, rolling integration/review/publication/
store suites plus exact new component selections frozen before editing. Prove
lexicographic order, honest upstream increases, invalid semantic/proof rejection,
scope changes versus instability, sampling boundaries/acknowledged waits,
restart recovery, stale candidates and serialized competing fast-forwards.
Verify every accepted merge produces the user-visible campaign completeness
vector for its integrated revision, rather than a stale worker-local value.
Feature integration runs the real Git/tag/DB path where configured; controlled
protocol fixtures are not represented as actual native-worker acceptance.
