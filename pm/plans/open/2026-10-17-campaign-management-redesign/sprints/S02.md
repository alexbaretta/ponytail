## Objective

Make the graph discoverable and checkable at actual entity boundaries. Use the
approved Q1 contract, without replacing semantic adequacy with annotation counts.

## Draft work packages

1. Add the approved successor graph/configuration schema and canonical identity
   readers; retain immutable historical readers and explicit normalization.
   Ensure inventory cannot omit an acceptance and still report full coverage.
2. Generalize relationship parsing and strict reference/role checking to all four
   edges. Enforce identified test-to-acceptance links and code-to-obligation links
   at stable blocks, not per-line annotations. Handle generated-source ownership.
3. Update TSTS semantic locators for the new annotation targets and test IDs;
   keep non-TypeScript graph ownership out of TSTS.
4. Update index ingestion, incremental invalidation, query/scoped traversal,
   coverage rules, reverse views and diagnostics. Scope cannot silently broaden.
5. Rewrite requirements-traceability and align requirements, UAT,
   typescript-unit-testing and production-test-boundaries. Synchronize only
   applicable source/generated consumers; adopted fixtures use the new contract.

## Owning surfaces

`skills/requirements-traceability/scripts/check-traceability.js` and typed
coverage rules; `tsts/src/traceability.ts`; `src/project-index.js`,
`src/traceability-projection.ts`, existing SQL/index-generation owners; the five
source skills, glossary, project traceability configuration, requirement/UAT
owners and version manifest. New/changed supporting code follows the prospective
TypeScript mandate; no unrelated index rewrite is authorized.

## Acceptance and proof

Missing, duplicate, dangling and wrong-kind IDs fail. One requirement with two
acceptances cannot pass merely because a test covers one. Adequate unit-only and
integration-only test coverage both work; many-to-many coverage does not require
duplicate assertions. Indexed and structural results agree, generated outputs
carry no duplicate annotations, and historical fixtures retain original meaning.

Focused owners: `tests/requirements-traceability*.test.js`,
`tests/traceability-projection.test.ts`, `tests/project-index.test.js`,
incremental/batch-resume integration fixtures, `tsts/test/traceability.test.ts`.
Use configured compiled test paths for TypeScript; build-impact precedes builds.
At the feature gate prove source → index → scoped query/reverse view → checker
through a disposable project, including an acceptance that lacks its own test.
