## Objective

Make the graph discoverable and checkable at actual entity boundaries. Use the
approved Q1 contract, without replacing semantic adequacy with annotation counts.

## Draft work packages

1. Add the approved successor graph/configuration schema and canonical identity
   readers; retain immutable historical readers and explicit normalization.
   Ensure inventory cannot omit an acceptance and still report full coverage.
2. Generalize relationship parsing and strict reference/role checking to all four
   edges. Enforce identified test-to-acceptance links and code-to-obligation links
   at stable blocks, not per-line annotations. Handle generated-source ownership.
3. Update TSTS semantic locators for the new annotation targets and test IDs;
   keep non-TypeScript graph ownership out of TSTS.
4. Update index ingestion, incremental invalidation, query/scoped traversal,
   coverage rules, reverse views and diagnostics. Scope cannot silently broaden.
5. Rewrite requirements-traceability and align requirements, UAT,
   typescript-unit-testing and production-test-boundaries. Synchronize only
   applicable source/generated consumers; adopted fixtures use the new contract.

## Acceptance and proof

Missing, duplicate, dangling and wrong-kind IDs fail. One requirement with two
acceptances cannot pass merely because a test covers one. Adequate unit-only and
integration-only test coverage both work; many-to-many coverage does not require
duplicate assertions. Indexed and structural results agree, generated outputs
carry no duplicate annotations, and historical fixtures retain original meaning.

Focused owners: `tests/requirements-traceability*.test.js`,
`tests/traceability-projection.test.ts`, `tests/project-index.test.js`,
incremental/batch-resume integration fixtures, `tsts/test/traceability.test.ts`.
Use configured compiled test paths for TypeScript; build-impact precedes builds.
At the feature gate prove source → index → scoped query/reverse view → checker
through a disposable project, including an acceptance that lacks its own test.


## First implementation slice: graph validation

The first independently testable component is a pure typed graph validator at
`skills/requirements-traceability/scripts/traceability-graph.ts`, with focused
proof in `tests/traceability-graph.test.ts`. It accepts discovered entities and
edges; filesystem/configuration discovery remains outside the component. This
separation allows malformed and incomplete graphs to be tested without an index,
Git repository or PostgreSQL and avoids embedding semantic approval in a parser.

Entity records carry stable ID, kind and locator. Kinds are requirement,
obligation, acceptance, unit-test, integration-test and implementation. Edge
records carry source ID, role and target ID. Legal triples are obligation /
decomposes / requirement; acceptance / verifies / obligation; either test kind /
verifies / acceptance; implementation / implements / obligation. Unknown IDs,
duplicate declarations and invalid triples produce stable diagnostics referencing
the source locator and implicated IDs. Identity is project-wide; a name reused
by a different kind is still a duplicate.

Coverage enumerates the discovered entity inventory, not just edge targets:
requirements need obligations, obligations need acceptances and implementations,
and acceptances need at least one executable test. An empty campaign scope is
not automatically proof that a project is complete. Missing structural coverage
is an input to assessment, not the final campaign completeness vector; passing
execution and semantic adequacy remain required by S04.

Required focused cases: fully linked graph; two acceptances with only one tested;
unit-only and integration-only coverage; multiple source/target links; duplicate
ID; unknown endpoint; wrong role/kind; implementation mapped directly to a
requirement rejected in V5; unrelated passing test cannot fill an acceptance gap.
Generated launch-path registration is owned by `scripts/build-runtime.ts` when
the structural checker begins consuming this component. Do not add a parallel
public checker command or manually maintained graph document.

## Executable graph component batch

### [DONE] Tasklet S02-F01-T01: Declare the graph contract

Own the entity-kind, entity, relationship, graph and finding contracts in
`skills/requirements-traceability/scripts/traceability-graph.ts`. Entities
contain ID, kind, path and line. Relationships contain source, target and role.
Input is already structurally parsed; semantic validation remains necessary.
No serialized version or filesystem behavior is introduced by this pure API.

### [DONE] Tasklet S02-F01-T02: Validate graph identity and coverage

In the same module, validate unique identities, resolved endpoints and the four
legal edge kinds before crediting coverage. Enumerate every entity for required
incoming and outgoing edges. Ignore invalid edges for coverage. Return stable
findings with affected identity and location. Do not return a campaign vector
or infer semantic adequacy. Use maps/sets to avoid repeated graph scans.

### [DONE] Tasklet S02-F01-T03: Prove the structural graph boundary

Own `tests/traceability-graph.test.ts`; call the real validator with exact typed
fixtures. Cover the first-slice cases above and orphaned source nodes. Build
only the affected root target after build-impact selection, then run
`node --test dist/tests/traceability-graph.test.js` and applicable TSTS.
Review the aggregate component before marking this feature complete.

This first component has no CLI consumer yet. Remaining S02 discovery, TSTS,
index and skill work remains required and will be added as ordered features
before editing their paths. S02 cannot be marked DONE after this component.

## Graph component verification

T01–T03 are implemented. Nine focused tests pass after the affected root build.
Adversarial review found traversal-dependent duplicate diagnostics; canonical
entity ordering and a same-kind/cross-kind duplicate regression test address it.
Final TSTS passes (1,713 files, no violations); independent reviewer recheck
confirms the fix and reports no further findings. This completes neither S02 nor
the campaign: source discovery, V5 configuration, TSTS attachment, index queries
and the skills remain required. Structural coverage does not prove adequacy.
