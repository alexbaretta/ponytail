## Objective

Provide a small independently testable validation/tag component and the approved
CLI interface. The Q2 design selects exact command names and typed physical
contracts before implementation; do not create guessed commands or a new ledger.

## Draft work packages

1. Implement the approved versioned validation certificate parser/writer and
   identity rules for focused delivery and campaign acceptance. Keep review
   attestation distinct from execution observations and scope definitions.
2. Capture actual configured command runs, selection/working directory, revision,
   relevant inputs/target, timestamps, results and applicable counts. Check
   pre/post input identity; do not issue a passing certificate for changed inputs,
   partial execution, mismatched selection, or an invented success statement.
3. Create/read/list exact annotated tags using the approved namespace and
   correction rules. Refuse overwrites and wrong target/object/payload versions.
   Optional failed-run recording is explicit, never automatic. Retain diagnostic
   output outside tracked source. Do not implicitly push tags or run release jobs.
4. Expose the same typed operation through CLI and any required MCP adapter;
   update help, generated runtime, contracts and temporary-artifact ownership.
5. Align evidence terminology and links in UAT, debugging, UX and their existing
   consumers; keep durable diagnosis/architecture distinct from captured output.

## Owning surfaces and proof

Reuse relevant Git freshness logic from
`skills/plan-execution/scripts/obligations.ts` and existing worker submission/
publication components where it conforms; do not inherit certificate ledgers.
New typed component paths and exact focused commands are frozen in S01/tasklet
planning, with CLI/help/MCP/runtime generation owners kept synchronized.

Prove in disposable Git repositories: two focused runs on one commit remain
distinct, tag payloads round-trip, failures cannot become passes, cancellation
does not certify partial success, changed source/configuration invalidates proof,
and tagging leaves HEAD, tracked files and index unchanged. Verify corrected
certificates preserve originals and final tags require the full QA selection.
No provenance can be manufactured from historical DONE or certificate prose.

## Validation contract implementation

The V1 request identifies campaign, exact candidate, focused/final purpose,
covered IDs, command argv arrays with their claimed test IDs, candidate-bound
review references, and whether a failed run may be recorded. The V1 certificate
embeds that request plus a unique run ID, start/end times and one observed result
per requested command. Result termination distinguishes exit, signal, spawn error
and not-run. A passing certificate requires every command to exit zero and
adequate review covering its claimed IDs; review remains an attestation, not a
tamper-proof guarantee that a runner executed the selection. S04 independently
compares final commands/scope against project full-QA configuration.

## Command execution and immutable tags

### [DONE] Tasklet S03-F02-T01: Run validation and publish exact-candidate tags

Own `src/validation-run.ts`. Run explicit argv arrays sequentially from the
invoking Git root, capture actual termination and raw output in the worktree's
Git metadata directory, and verify a clean exact candidate before/after commands
and immediately before publication. Reject concealed index changes. Preserve
HEAD, source and index. Publish immutable annotated tags through atomic ref
creation with candidate verification; read/list tags only after target/payload

process group and wait for cleanup before returning. No implicit shell or push.
Final-purpose tags still require S04's independent configured-full-QA gate.

## Execution/tag component verification

Ten contract and real-process/Git tests pass. Runs on the same commit create
distinct annotated tags while preserving source, index entries and HEAD. Failed

No production tags were created. Revocation/correction handling, public CLI/MCP

## Revocation and historical inspection

### [DONE] Tasklet S03-F03-T01: Invalidate certificates without replacing tags

Git tag parsing/publication shared rather than adding a parallel implementation.
