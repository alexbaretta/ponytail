## Objective

Export one campaign methodology using native sessions and retire the old swarm
chapter without a renamed equivalent. Host behavior must be described honestly;
the skill cannot guarantee uninterruptible goals or unsupported timer semantics.

## Draft work packages

1. Create campaign-management as the successor to swarm, using the shared
   glossary. Define complete assignment goals, message authority, local reviewer
   obligations, blocked/idle/ready/DONE handling, target replenishment, retained
   blockers, resumed excess capacity, and short coordinator service/wakeup loop.
   Apply the design record's worker naming convention through native host tools:
   campaign identity, campaign-local sequence, three-letter assignment summary,
   and a single DONE prefix only at final completion. Preserve sequence identity
   across blocked/resumed workers and give replacements new numbers.
2. Replace worktree-lifecycle's campaign/pool policy while retaining host
   ownership, unfinished source and project-resource cleanup. Preserve blocked
   checkouts; do not infer abandonment from silence or retire them for capacity.
3. Edit plan-execution and ponytail to reference the new controller; align
   issue-tracking, project-structure, semantic-rebase, architecture, debugging
   and UX. Preserve ordinary planning, explicit authority, real-path QA and
   continuation-blocker boundaries. Reconcile exact tasklet versus outcome scope.
4. Remove exported parallel-plan-scheduler and qa-swarm. Salvage only necessary
   historical-reader instructions and exhaustive, revision-consistent QA slicing
   into references owned by the remaining skills. No duplicate coordination mode.
5. Remove `swarm` dispatch/help/MCP exposure and obsolete campaign-native
   allocation, lease/queue/session mutation surfaces per the approved matrix.
   Audit plan-input, worktree recovery and rebase callers before removing shared
   code; preserve unrelated features and historical inspection.
6. Update registry, installer stale-owned-file reconciliation, permissions,
   command completion/help and plugin metadata. Regenerate runtime, host copies,
   adapters, manifests and registry data through their owners, recording
   pre-generation state and undoing incidental unrelated edits.

## Owning surfaces and proof

`registry.tsv`, canonical skill sources/references and metadata,
`cli/ponytail`, `src/cli-help.ts`, rolling/swarm command owners,
`ponytail-mcp/index.ts` and `rolling.ts`, `scripts/build-*.js`/runtime generator,
installers, host/package manifests and synchronized project instructions.

Focused owners include swarm/QA policy and integration tests, command/CLI/MCP
registry tests, semantic-rebase policy/worker tests, rule copies, distribution,
OpenClaw and installer lifecycle tests. Retire assertions enforcing obsolete
behavior, not valuable isolation/ownership tests. Prove target ten, blocked
replacement on other work, human-unblocked excess, completion-based replenishment,
idle recovery, no compatible work, and no coordinator review/rebase. Verify
worker names identify their campaign and unique sequence, use three-letter
summaries, and gain exactly one DONE prefix only on final completion. Validate
retirement/help parity and absence of stale exported skill files after upgrade.
