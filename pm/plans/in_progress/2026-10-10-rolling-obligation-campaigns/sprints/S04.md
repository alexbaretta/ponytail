## Feature S04-F01: Managed checkouts

Acceptance: ordinary Git checkouts reside in the same physical configured pool
for every registered worktree, with numbers >=101. Setup repairs marker ignore
policy. Reuse preserves work and requires an explicitly retired prior owner;
dirty, divergent, unknown or incorrectly registered roots are rejected. Retained
caches do not establish ownership. Database intents precede external effects.

### [DONE] Tasklet S04-F01-T01: Resolve and validate the physical pool

Declaration: resolveRollingManagedDirectory in src/rolling-worktrees.js. Read
only the invoking repository's explicit registered-worktree inventory. Resolve
relative configuration against the Git main worktree, not each worker cwd.
Resolve existing symlink ancestors physically even when the directory itself
is not created yet. An in-main-checkout pool must already be Git ignored to
preserve a clean integration checkout; reject before creating any directory if
this project setup prerequisite is missing. Require each registered checkout's project configuration to
resolve to that same physical directory. Reject missing or ambiguous authority.

### [DONE] Tasklet S04-F01-T02: Provision and prepare leased checkouts

Declaration: provisionRollingWorktree and ensureRollingSessionIdIgnored in
src/rolling-worktrees.js. Validate the reserved number/path and full base commit;
use a generation-specific ordinary branch. Run project argv setup in the exact
checkout with its number/root/main-root environment. Require marker absence and
Git ignore behavior. Reuse only clean integrated ancestry; preserve divergent
and uncommitted work. Retry only the identical provision intent. Setup failures
remain assigned for operation-layer quarantine/recovery.

### [DONE] Tasklet S04-F01-T03: Prove the real Git lifecycle

Files: tests/rolling-worktrees.test.js and
 tests/rolling-worktrees.integration.test.js. Disposable repository fixtures
exercise shared physical paths, relative anchoring, numbers, setup cwd, marker
ignore, same-intent recovery, clean reuse and rejection preserving dirty or
unintegrated work. No active Ponytail project worktree is created by this proof.

## Checkout feature evidence

Two focused tests pass with zero failures or skips. The real Git Arc proves
main-root relative resolution from a linked checkout, exact setup cwd/number,
identical provisioning intent recovery, marker ignore repair, marker/dirty/
divergent preservation gates, integrated branch reuse and retained registration
after setup failure. A pool inside the main checkout is ignored and provisioning
leaves the main checkout clean; an unignored pool is rejected before creation.
Physical-path unit proof covers symlink ancestors and
missing descendants. All created checkouts live in disposable fixture trees
removed at test completion; no active project worker checkout was created.
Build-impact reports no affected or indeterminate targets.

The installed App Server protocol generator confirms thread/start and
thread/resume cwd and returned session identity. Its CLI also exposes a stdio
proxy to a running persistent daemon. The native adapter must use that canonical
connection without restarting or stopping the shared daemon. Direct native
startup, live identity/instruction proof and database action dispatch remain
pending; S04 remains IN_PROGRESS. No plugin dependency has been introduced.

Project structure validation passes: 1 plan, 4 sprints, 21 tasklets. TSTS
checked 714 files with no violations. Nine traceability coverage gaps remain
for review, publication and interfaces; native worker acceptance also remains
unproven despite existing checkout implementation/test relationships.
