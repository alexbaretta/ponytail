## Scope and order

1. Establish a strict root TypeScript project, emitted-runtime ownership,
   canonical build command and build-impact target. Apply existing TSTS to root
   TypeScript in addition to its existing self-check. Require strict compiler
   checks, checked indexed access and exact optional properties. `allowJs` and
   `checkJs` are not migration completion paths.
2. Convert the uncommitted native Codex transport and its protocol fixture,
   unit tests and explicit live smoke Arc. Use named contracts, validated
   `unknown` at native JSON boundaries, typed pending requests/events/errors,
   and a typed subprocess fixture instead of a handwritten JavaScript string.
3. Convert portable obligations and rolling configuration/graph/store/worktree
   modules, with their focused proofs. PostgreSQL and native protocol results
   enter owned code through validated boundaries. Preserve V1 meanings and
   atomic action fencing; synchronize contract source-owner paths.
4. Convert remaining owned implementation, CLI, hooks, portable skill scripts,
   build/install/QA tooling, host adapters and tests. Preserve host module and
   launch conventions with generated JavaScript emitted from checked TypeScript.
   Generated copies derive from canonical typed owners. Do not add untyped
   declarations to conceal remaining JavaScript dependencies.
5. Reconcile other handwritten executable languages with the stakeholder's
   statically typed language restriction. Replace Python/shell/PowerShell logic
   with typed implementation; host-required entrypoint wrappers are generated
   launch artifacts. Preserve the existing benchmark boundary: its migration
   does not make core build, QA or packaging execute benchmark behavior.
6. Update installation, packaging, command paths, generated adapters, project
   structure, traceability and documentation atomically with migrated owners.
   Resume S04/S05/S06 on typed sources and rerun final applicable acceptance.
