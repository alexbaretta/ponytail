## Frozen design and acceptance

New root config V3 preserves V2's exact physical shape and reader. It adds
`sharedMessageContracts` with canonical exported tuple-map declarations,
configured receiver declarations/methods and parameter positions, producer
or consumer roles, raw dependency API flags, and designated exported adapter
functions returning a configured typed receiver. Contract/API IDs are unique.
All configured calls are discovered by compiler signature declaration identity,
independent of channel registration, including extracted methods. Channels are
finite string-literal unions (or constrained generics); contracts have no index
signature and every required property is a typed tuple. Each exposed overload
must bind its channel parameter to the same canonical indexed argument tuple.
Consumer listener signatures and explicit handler annotations derive from
that tuple; contextual inference is accepted. Generic tuple helper aliases
are resolved through declarations with type-parameter bindings.

Raw APIs must originate in dependency declaration files, never owned source.
They may be called only within configured adapter exports with the canonical
typed return interface. Channel discovery still applies inside adapters.
External-input runtime validation remains a separate requirement, not a claim
this static checker can prove. Paths resolve relative to config; diagnostics
identify locations, offending APIs and canonical remediation.

Each tasklet below owns one type, function or validation gate. Shared paths
are sequentially ordered. Record modest algorithms here instead of repeating
every source branch in prose; more detailed duplication would cost more than
the declaration-sized edits. Focused fixtures invoke the real checkProject,
compile valid shared contracts, reject object sends with TypeScript, and
exercise the real CLI. Test/config data uses exact production types.
