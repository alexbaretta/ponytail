## Feature S01-F01: Original-owner resolution

### [DONE] Tasklet S01-F01-T01: Implement the checked inventory boundary

Implement `resolveSwarmOwner` over typed user/managed inventory records. Keep
user swarms independent, resolve managed ownership through the recorded owner,
and reject unknown, unassigned, contradictory, duplicate and foreign-repository
records. Add focused unit proof and canonical runtime/traceability mappings.
Three focused tests pass; this is core proof, not installed CLI or live DB proof.

### [DONE] Tasklet S01-F01-T02: Verify physical inventory and CLI routing

Bind the typed inventory to canonical physical Git/DB facts and the installed
swarm chapter. Prove selection from a user checkout and its managed checkout,
and isolation from a sibling owner. Run focused physical/CLI integration proof,
then assess OBL-1 against the whole canonical discharge criterion. The pure
resolver alone does not discharge this tasklet or the obligation.

Evidence: typed owner/unit proof passes five tests and the real Git/PostgreSQL
inventory Arc passes. Actual installed `ponytail swarm info` reports the empty
Ponytail owner successfully; chapter and command help are wrapped and inert.
The same canonical reader reports GWEN's seven existing leases, including an
unattached reservation, with coordinator/native activity explicitly unrecorded.
No live session, lease or campaign state was changed. Swarm-specific role
bindings and native activity remain subsequent obligations, not completed work.

## Feature S01-F02: Explicit owner and coordinator persistence

### [DONE] Tasklet S01-F02-T01: Persist exclusive coordinator bindings

Scope: `src/swarm-store.ts`, `scripts/project-index.sql`,
`tests/swarm-store.integration.test.ts`, their generated runtime and project
configuration/traceability mappings. OBL-1 and OBL-2 own the conditions.
Enroll canonical physical user checkouts and reject managed checkout enrollment.
Use one owner row to enforce coordinator exclusivity; reject stale unbinding
without deleting campaign assignments or checkouts. Enrollment and low-level
binding are independently tested before exposing the native CLI adapter.

Focused real PostgreSQL proof passes: two simultaneous binds yield one winner;
same-session binding is idempotent; a stale unbind cannot remove the winner;
unbinding preserves worker assignments and physical checkout state. The test was
added after the initial implementation draft, so it does not establish the
cross-session-effects skill's failing-first gate. Native identity validation,
explicit worker membership adoption and native CLI acceptance were deferred to
the following tasklet. OBL-2 is not discharged by low-level storage proof.

Adversarial review identified retained managed checkouts without DB rows and
missing/replaced enrolled roots as admission gaps. New regressions failed on
each missing rejection before its fix. Enrollment now reads the canonical
configured physical pool and excludes managed paths even after reset, under
the existing project advisory fence. Coordinator binding rechecks the retained
physical Git identity before its transaction commits.

### [IN_PROGRESS] Tasklet S01-F02-T02: Expose original coordinator binding

Scope: `src/swarm-info.ts`, `src/cli-help.ts`, `tests/swarm-info.test.ts`,
`tests/swarm-info.integration.test.ts`, `tests/swarm-store.integration.test.ts`,
`tests/cli-help.test.ts`, generated runtimes/registry, versioned contract manifest
and project documentation. Check original native identity without acquiring its
writer before binding. Expose bind/unbind in the swarm chapter with wrapped
scoped help; report explicit bound/unbound state via V2 while preserving V1.

Focused proof passes 22 unit/help/protocol tests and both real PostgreSQL integration
tests. Controlled native observation rejects identity mismatch and succeeds
while writer resumption is refused. The real unbind CLI selects the owner from
a managed checkout, rejects stale IDs and preserves workers. Full live native
binding acceptance and explicit worker adoption remain pending. No GWEN session
or live campaign record was changed.

Adversarial review found a thread/session ID conflation masked by the protocol
fixture and a managed-checkout bind routing gap. The adapter now requires both
IDs, observes the actual original thread, and persists their canonical native
mapping; the fixture rejects unknown thread IDs. A real CLI test with a controlled
native executable proves binding from a managed invocation to its user owner.
`owner-enroll` explicitly declares a new user checkout's previously unknown role;
it does not guess that an unassigned managed root is an owner. Live native
binding acceptance remains pending.
