## Objective

Deliver `REQ-FAST-SEMANTIC-REBASE` after implementation kickoff: one aggregate
final-state review identifies semantic-conflict source hunks, and Ponytail
performs the remaining history analysis and interactive-rebase mechanics
without language-specific inference or rebase-time product validation.

## Dependencies and execution gate

No other plan is a prerequisite. The stakeholder explicitly approved kickoff,
the plan moved to `in_progress`, activation reconciled
`REQ-FAST-SEMANTIC-REBASE` with architecture, UAT, traceability, and the
canonical obligation baseline, and the detailed tasklets passed atomicity
review. The configured starting checkpoint remains the gate before product
edits.

## Resolved design decisions

- `[RESOLVED]` `diff` reviews aggregate `base..target` and `base..source`
  changes, not each source commit.
- `[RESOLVED]` The review bundle is deterministic human-readable text with
  stable frozen-analysis IDs; internal state remains a strict versioned typed
  contract.
- `[RESOLVED]` The agent may relate source and target changes across files.
- `[RESOLVED]` Contributor mapping is backward/forward diff lineage with an
  affected-path fallback, not `git blame` alone.
- `[RESOLVED]` Git interactive rebase remains the replay engine and always
  stops on unexpected textual conflicts.
- `[RESOLVED]` No rebase command runs tests, builds, or QA.

## Feature S01-F02: Agent selection and commit lineage

Status: DONE

Acceptance: an agent-authored source/target conflict list maps every selected
source change to every proven contributor commit and widens no farther than
the affected path lineage when exact attribution is unavailable.

### [DONE] Tasklet S01-F02-T01: Define the conflict-selection contract

Define and strictly parse the V1 line-oriented conflict-selection document.
Each entry names one source change ID, zero or more related target IDs, and an
optional uninterpreted reason. Bind it to the frozen analysis digest; reject
unknown, duplicate, cross-analysis, target-only, and malformed selections.

### [DONE] Tasklet S01-F02-T02: Map selected hunks to contributor commits

Implement rename-aware interval lineage across the frozen ordered source
commits. Walk final added or modified intervals backward, deleted base
intervals forward, and mark every commit that creates, removes, replaces, or
changes tracked content. For ambiguous, binary, submodule, symlink, or
whole-file lineage, mark every commit touching only the affected path lineage.

### [DONE] Tasklet S01-F02-T03: Validate selection and lineage

Prove cross-file source/target selections, multi-commit hunk construction,
later modification of earlier lines, deletion, rename, shifted intervals,
ambiguous fallback, malformed selection, and deterministic contributor order.
Confirm that target IDs provide context but only selected source IDs create
planned stops.

## Feature S01-F03: Retained interactive replay

Status: DONE

Acceptance: Ponytail safely starts, observes, continues, and aborts the exact
frozen replay, stopping at every selected contributor and every unexpected Git
conflict without updating unrelated refs or invoking product validation.

### [DONE] Tasklet S01-F03-T01: Start the selected replay

Implement `run` with a generated interactive-rebase todo that inserts `break`
after selected contributors and leaves other source commits as `pick`. Require a clean attached
branch and matching frozen analysis/selection; use `--no-autostash`,
`--no-autosquash`, and `--no-update-refs`; retain exact pre-run identity; and
return a self-contained current-stop dossier.

### [DONE] Tasklet S01-F03-T02: Continue reviewed replay

Implement `continue` validation for the expected original commit, selected
lineage, resolved index, retained Git rebase markers, source/target identity,
and understood checkout changes. Continue ordinary selected stops; when a
resolution changes content outside selected lineage, retain the rebase and
emit a residual aggregate review instead of proceeding automatically.

### [DONE] Tasklet S01-F03-T03: Report retained replay status

Implement read-only `status` output for inactive analysis, prepared replay,
selected stop, unexpected textual conflict, residual-review requirement, and
completed replay. Reprint the current dossier from durable state so prior
stdout is never the only source of truth.

### [DONE] Tasklet S01-F03-T04: Abort retained replay

Implement idempotent `abort` that delegates replay restoration to Git,
verifies the invoking branch returns to the exact frozen source tip, removes
only the worktree-local Ponytail rebase state, and refuses foreign or
mismatched rebase state without deleting user work.

### [DONE] Tasklet S01-F03-T05: Validate the replay lifecycle

Using isolated real-Git fixtures, prove selected and unselected clean replay,
multiple contributing commits, unexpected textual conflict, selected semantic
amendment, broadened-resolution invalidation, stale source/target/selection,
dirty-start refusal, status recovery, idempotent abort, retained unrelated
refs with `rebase.updateRefs=true`, and zero test/build/QA/fetch/push commands
inside the rebase lifecycle.
