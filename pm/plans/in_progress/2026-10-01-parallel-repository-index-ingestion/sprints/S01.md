transaction batches while preserving durable progress, writer exclusion,
atomic publication, restart, and cancellation behavior.

### [DONE] Tasklet S01-F01-T02: Ingest complete commit batches

Extract one canonical preparation and insertion path for one or more complete
commits. Insert shared documents/blobs and commit-owned rows in deterministic
order, commit each batch atomically, and report only rows made durable. Preserve
the injectable pool boundary used by focused tests.

Traceability: plans-implementation REQ-REPOSITORY-TEXT-INDEX from tasklet S01-F01-T02

Implementation evidence (2026-10-01): one batch function prepares every commit
and blob before opening its transaction, then inserts documents by content ID,
blobs by Git OID, and commit-owned rows by stable commit/path keys. A batch
commits or rolls back as a unit, and both serial and process workers use this
same function.

### [DONE] Tasklet S01-F01-T03: Coordinate real worker processes

Implement a coordinator-owned pull queue and actual worker processes. Retain
the parent advisory lock and final publication authority; on abort or worker
failure stop assignment, notify and drain every worker, roll back unfinished
transactions, propagate the first failure, and leave no child alive.

Traceability: plans-implementation REQ-REPOSITORY-TEXT-INDEX from tasklet S01-F01-T03

Implementation evidence (2026-10-01): the lock-owning coordinator forks the
selected number of workers and assigns disjoint batches from one in-memory
queue. It serializes durable progress, stops assignment on abort or failure,
signals every child, waits for all exits, and retains sole authority for final
ref and overlay publication. The isolated acceptance observed three distinct
worker PIDs and no surviving worker after success or interruption.
