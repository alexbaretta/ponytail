## Feature S03-F01: Transactional allocation and durable lifecycle

Acceptance: actual PostgreSQL enforces exclusive ownership and capacity under
contention; inactive workers retain checkout ownership while freeing capacity;
release/allocate is atomic and no-ready release succeeds; stale snapshots and
lease generations cannot mutate accepted state. External intents are idempotent
and inspectable. Graph definitions remain in coordinator files.

### [DONE] Tasklet S03-F01-T01: Declare execution tables and indexes

Files: scripts/project-index.sql (existing schema/setup path), package.json
packaging remains existing SQL owner. Add versioned pool/campaign/worktree/
assignment/action tables under ponytail_index and existing owner grants. Bind
all rows to project identity, enforce unique pool number/path, unique live
obligation/worktree ownership including inactive leases, positive safe capacities,
and enumerated states. Partial ordered indexes cover available numbers and
pending actions. No new database, role or cloud service is introduced.

### [DONE] Tasklet S03-F01-T02: Serialize allocation and graph reconciliation

Declaration: RollingCampaignStore in src/rolling-campaign-store.js. Constructor
accepts the configured PostgreSQL pool and project identity. Every mutation
locks the project pool then campaign inside one transaction; read coordinator
files from the persisted root/paths after locking. Compare the database accepted
graph digest and explicit expected digest to the fresh graph. Select through
S02; choose lowest available number or lowest unused number >=101. Reserve
checkout, assignment and external intent atomically. PostgreSQL JSON read as
text before owned lossless conversion. Parameterized SQL only.

### [DONE] Tasklet S03-F01-T03: Fence suspension, release and reactivation

Methods: suspend, retire/release through allocate, action completion. Require
expected lease generation; inactivity requires stopped activity acknowledgment.
Retirement acknowledgment precedes availability. Released assignments retain
history; no-ready result commits release. Resume original session and checkout
before creating a new assignment. Unknown outcomes cannot be retried as new starts.

### [DONE] Tasklet S03-F01-T04: Persist next actions and recover acknowledgments

Methods: status, nextActions, acknowledgeAction. Expose pending durable intents,
exact identities and reasons. Idempotency keys and completion state fence repeats;
external host/filesystem/Git results remain distinct from SQL transaction success.
No worker or publication result is inferred from a reservation alone.
