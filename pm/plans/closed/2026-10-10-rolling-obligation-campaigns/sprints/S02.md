## Feature S02-F01: Independently testable rolling configuration and scheduling

Acceptance: project input is strictly parsed, resolved configuration persists
explicit target/defaults, coordinator graph identity changes on relevant inputs,
and ready compatible obligations are selected deterministically with resume first.
Starting unit evidence is inherited from S01; missing new implementation/test
coverage is owned by this sprint and the final plan, not waived.

### [DONE] Tasklet S02-F01-T01: Parse the project configuration V1

Declaration: readRollingProjectConfigV1 in src/rolling-campaign.js. Exact fields:
schemaVersion, mainline, managedWorktrees, maxActiveWorkers, publicationSize,
setupCommands, qa. mainline is null or remote/branch; managedWorktrees owns directory
and anchor=main; nullable N/M mean global defaults. setup and QA use argv arrays,
never shell text. Validate exact keys, nonempty strings, positive safe integers
and nonempty publication QA. parseRollingProjectConfig performs lossless number
conversion only for safe integers. Register immutable V1 reader in the contract
manifest. tests/rolling-campaign.test.js proves precision, executable argument
preservation, unsupported schema/keys and malformed commands. No DB or host call.

### [DONE] Tasklet S02-F01-T02: Resolve campaign defaults and refs

Declaration: resolveRollingConfiguration; reads explicit overrides, project
values and effective Git init.defaultBranch in order. Persist origin/explicit
remote plus valid target refs; verify remote branch existence separately before
campaign activation. Do not mutate defaults or infer creation authority.
Proof: precedence, N/M default/invalid values and fixed target after config edits.

### [DONE] Tasklet S02-F01-T03: Collect the authoritative graph

Declaration: collectRollingGraph; only designated coordinator root and canonical
obligation document. Reuse obligation parsing and freshness assessment, hash
source/configuration and accepted inputs. Reject escaping paths and stale source
identity. Proof: worker-copy differences do not control scheduling, dependencies
and cycles are handled by the canonical reader, changed inputs change digest.

### [DONE] Tasklet S02-F01-T04: Select compatible obligations with resume first

Declaration: selectRollingAssignments; derive readiness from graph and current
ownership, acknowledge inactive state before subtracting capacity, prefer eligible
resumptions, then category/stable numeric ID. Conservatively reject overlapping
write paths and exclusive resource claims. Greedy maximal selection bounded by N.
Proof: saturation, dependencies, stable numeric ordering, retained inactive claims,
conflicts and stale graph rejection. S03 supplies atomic concurrency enforcement.

### [DONE] Tasklet S02-F01-T06: Load project configuration at the coordinator boundary

Declaration: loadRollingConfiguration in src/rolling-campaign.js. Inputs: explicit
coordinator root and request. Validate the exact Git checkout root; read only its
canonical non-symlink rolling configuration file and effective init.defaultBranch.
Return resolved configuration without creating refs/resources. Fail missing or
foreign-root inputs rather than falling back. Integration proof in
tests/rolling-campaign.integration.test.js uses real isolated Git repositories,
canonical configuration files and effective local Git defaults.

### [DONE] Tasklet S02-F01-T05: Validate the combined core boundary

Run node --test tests/rolling-campaign.test.js, portable obligation validation,
manifest checks and changed-source build-impact. Register actual source and
verification relationships; remaining integration proof belongs to S03-S06.

Configuration proof established physical V1 parsing, default resolution and
real Git loading. Graph/scheduling proof now establishes the combined core
boundary. CLI wiring and physical pool checks remain S04/S06 responsibilities;
no whole configuration requirement discharge is claimed from core proof alone.

Configuration change-set also synchronizes AGENTS.md, PROJECT_STRUCTURE.md, the
versioned contract manifest and actual traceability classifications. The
source/command boundary rejects symlinked configuration ancestors. Build-impact
reported no affected or indeterminate targets. No build was required.


Graph execution bindings are a separately versioned V1 plan-side document;
canonical obligation V1 fields/readers remain unchanged. Exact shape:
`schemaVersion`, `bindings`; each binding owns obligationId, implementationIds,
sourcePaths, acceptances (id/arcId/nullable stepId), unitTests and integrationTests
(id/path/nonempty selection), and exclusiveResources. These are execution
references, not a competing satisfaction or relationship registry. Validate IDs
against the canonical obligation document; unknown or missing bindings prevent
allocation. Canonical relationship reconciliation remains a final gate.

The graph collector takes explicit coordinator root, obligation path and binding
path, reads the canonical project configuration, and hashes HEAD, document/config
bytes and assessed requirement/certificate input digests. Scheduler receives that
snapshot, its expected digest, positive capacity, and current assignment records.
Active/inactive records retain frozen plannedPaths/resource claims. Inactive
requires acknowledged activityStopped; terminal RELEASED records consume neither
capacity nor ownership. No scheduler mutation itself supplies database atomicity.


S02 acceptance: focused unit/real Git integration command passed 11 cases, zero
failures/skips. Graph inputs are pinned to the designated coordinator checkout;
HEAD, authoritative files and assessed inputs participate in identity. Scheduling
is pure and leaves exclusive state transitions to S03 PostgreSQL transactions.
Suspended scope changes require reconciliation, and other campaign ownership
still constrains shared paths. Missing bindings are blocked rather than guessed.
No native worker lifecycle or publication acceptance is claimed by this sprint.

Required inputs unavailable to the coordinator now prevent all new/resumed
allocations and are reported explicitly; no missing-file exception is treated
as graph readiness. TSTS checked 703 files with no violations.
