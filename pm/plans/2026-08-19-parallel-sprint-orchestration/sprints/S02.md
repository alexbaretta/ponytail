## Objective

Add read-only, standard-library Node.js tools that select planning-ready sprint
stubs, execution-ready planned sprints, and the deterministic next tasklet
within one sprint.

## Delegation

- Intended owner: one implementation subagent in parallel with S01 after plan
  approval.
- Preferred model: the least expensive available model judged capable of
  implementing the fully specified functions below.
- Interference boundary: this sprint owns only its skill-local scripts, focused
  tool tests, sprint record, and tasklet scheduling metadata.

## Questions

- No open questions. Input, validation, algorithms, output, and failure
  behavior are fixed below.

## Feature F01: Metadata and graph model

Acceptance: The tool constructs one validated in-memory sprint graph without
dependencies beyond the Node.js standard library.

### [DONE] Tasklet S02-F01-T01: Create Tool Module Envelope

- Create `skills/plan-execution/scripts/ready-sprints.js` with the repository's
  copyright and license header.
- Import only `node:fs` and `node:path`.
- Declare the metadata marker and the planning and execution status sets once.
- Export the named functions implemented by later tasklets.
- Add a `require.main === module` branch that invokes `main` and reports one
  actionable error to standard error with nonzero exit status.
- Do not implement a second parsing or execution path.

### [DONE] Tasklet S02-F01-T02: Implement Sprint Metadata Parser

- Implement one `parseSprintFile(filePath, text)` function.
- Require exactly one block delimited by `<!-- ponytail-plan-sprint` and
  `-->`; parse its body with `JSON.parse`.
- Require exactly `id`, `planning`, and `execution`; require exactly `status`,
  `depends_on`, and `scope_roots` under planning.
- Permit `execution` to be `null` until detailed planning is ready for review;
  otherwise require exactly `status`, `depends_on`, and `planned_paths`.
- Require the ID to equal the sprint filename without `.md`, both statuses to
  be allowed, and all collections to contain unique strings.
- Validate every root and path as a nonempty `/`-separated relative value
  without empty, `.`, or `..` segments, backslashes, or glob metacharacters.
- Return a plain object containing the validated values and source filename.

### [DONE] Tasklet S02-F01-T03: Implement Plan Sprint Reader

- Implement one `readSprints(planDirectory)` function.
- Read only regular `SNN.md` files directly inside `<plan>/sprints`, sorted by
  numeric sprint ID.
- Parse each through `parseSprintFile` and reject duplicate IDs.
- Reject an absent sprint directory or an empty sprint set actionably.
- Perform no filesystem writes.

### [DONE] Tasklet S02-F01-T04: Implement Dependency Validator

- Implement one `validateDependencies(sprints)` function.
- Build a map keyed by sprint ID.
- Validate the planning and execution dependency graphs independently.
- Reject unknown dependencies and self-dependencies in either graph.
- Detect cycles with depth-first traversal using `visiting` and `visited` sets;
  identify the lifecycle and discovered cycle path in the error.
- Return the ID map for reuse rather than constructing a parallel graph model.

### [DONE] Tasklet S02-F01-T05: Implement Path-Interference Validator

- Implement one `validatePathOwnership(sprints, sprintById)` function.
- Compute transitive dependency reachability with memoized depth-first
  traversal over the validated execution graph.
- Ignore stubs whose execution metadata is still `null`.
- Compare every sprint pair. Permit a shared exact path only if either sprint
  transitively depends on the other.
- Reject the first unordered overlap with both sprint IDs and the path.
- Do not interpret globs or inspect whether a declared path currently exists.

## Feature F02: Ready-set selection and CLI

Acceptance: Valid plans yield a deterministic machine-readable ready set and
invalid plans fail without mutation.

### [DONE] Tasklet S02-F02-T01: Implement Planning-Ready Sprint Selection

- Implement one `selectPlanningReadySprints(sprints, sprintById)` function.
- Select only `STUB` sprints for which every direct planning dependency is
  `APPROVED`.
- Return their IDs in numeric sprint order.
- Treat every other planning status as not ready; do not infer or modify state.

### [DONE] Tasklet S02-F02-T02: Implement Execution-Ready Sprint Selection

- Implement one `selectExecutionReadySprints(sprints, sprintById)` function.
- Select only sprints whose planning is `APPROVED`, execution metadata exists,
  execution status is `PENDING`, and every direct execution dependency is
  `DONE`.
- Return their IDs in numeric sprint order and do not infer or modify state.

### [DONE] Tasklet S02-F02-T03: Implement Read-Only CLI Main

- Implement one `main(argv)` function.
- Require exactly `planning` or `execution` plus one plan-directory argument.
- Resolve the directory, read sprints, validate dependencies, validate path
  ownership for execution, and select the requested ready set through the
  canonical function.
- Write exactly one JSON array plus a newline to standard output.
- Return no alternate human-output mode and perform no writes.

## Feature F04: Sprint-local tasklet selector

Acceptance: The selector validates the tasklet graph and returns exactly one
ready tasklet through the documented lexicographic priority contract.

### [DONE] Tasklet S02-F04-T01: Create Tasklet Selector Module Envelope

- Create `skills/plan-execution/scripts/next-tasklet.js` with the repository's
  copyright and license header.
- Import only Node.js standard-library modules.
- Declare allowed tasklet statuses and risk values once.
- Export the named functions implemented by later tasklets.
- Add one `require.main === module` branch that invokes `main` and reports one
  actionable standard-error diagnostic with nonzero failure status.

### [DONE] Tasklet S02-F04-T02: Implement Tasklet Status Parser

- Implement one `parseTaskletStatuses(sprintFile, text)` function.
- Parse every canonical tasklet heading and its `[ ]`, `[DONE]`, or `[ERROR]`
  marker from the Markdown.
- Reject duplicate tasklet IDs and malformed tasklet headings.
- Return one map keyed by tasklet ID without interpreting tasklet prose.

### [DONE] Tasklet S02-F04-T03: Implement Tasklet Metadata Parser

- Implement one `readTaskletGraph(sprintFile)` function.
- Derive the sibling `SNN.tasklets.json` path from the sprint filename and
  parse strict JSON.
- Require exactly `sprint` and `tasklets` at the root and require every node to
  contain `depends_on`, `affinity`, and `risk`, plus `risk_reason` only when
  risk is `high`.
- Require unique string arrays, known risk values, matching sprint IDs, and an
  exact one-to-one node set with the parsed Markdown statuses.
- Reject descriptions, statuses, derived reverse edges, scores, or duration
  estimates in scheduling metadata.

### [DONE] Tasklet S02-F04-T04: Implement Tasklet Graph Validator

- Implement one `validateTaskletGraph(graph, statuses)` function.
- Reject unknown and self dependencies, dependencies on `[ERROR]` tasklets,
  cycles with the discovered path, and a completed tasklet that depends on an
  unfinished tasklet.
- Derive reverse edges for unfinished descendant counts and memoize longest
  remaining dependency depth without persisting either value.
- Return the validated derived data needed by selection rather than building a
  second graph representation.

### [DONE] Tasklet S02-F04-T05: Implement Deterministic Tasklet Selection

- Implement one `selectNextTasklet(graph, statuses, derived, lastTasklet)`
  function.
- Form the ready set from `[ ]` tasklets whose dependencies are all `[DONE]`.
- Compare ready nodes lexicographically by high risk, affinity overlap with the
  last completed tasklet, unfinished descendant count, longest remaining
  dependency depth, and lowest tasklet ID.
- Treat affinity as neutral when there is no last tasklet.
- Return the selected ID and only the criterion values that determined the
  choice. Return `{"next":null}` with no criteria for a fully `[DONE]` graph;
  reject an unfinished graph with no ready node.

### [DONE] Tasklet S02-F04-T06: Implement Tasklet Selector CLI Main

- Implement one `main(argv)` function.
- Require one sprint Markdown path and accept one optional last-completed
  tasklet ID.
- Parse statuses and metadata, validate, select, and write exactly one stable
  JSON object plus a newline.
- Reject an unknown or non-`[DONE]` last tasklet and perform no writes.

### [DONE] Tasklet S02-F04-T07: Prove Tasklet Scheduling Behavior

- Create `tests/next-tasklet.test.js` with `node:test`, strict assertions, and
  temporary Markdown and JSON fixtures.
- Cover node-set mismatch, malformed headings and metadata, invalid risk,
  missing high-risk reason, unknown and self dependencies, `[ERROR]`
  dependency, cycles, invalid completed dependencies, and no-ready-node
  failure.
- Prove each lexicographic criterion independently, stable ID tie-breaking,
  neutral first-task affinity, exact CLI output, actionable failure, and no
  filesystem mutation.
- Focused validation: `node --test tests/next-tasklet.test.js`.
