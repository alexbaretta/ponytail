# Sprint S04: Generate Supported Host Adapters

Status: `DONE`

## Objective

Replace manually drifting skill, command, and adapter inventories with
one declarative registry and integrate project-local skill roots without
copying their contents into Ponytail.

## Dependencies

- Sprint S03 is `DONE`.
- Decisions D18, D21, D22, D24, and D25.

## Questions

No open questions.

## Feature F01: Canonical Registry

### [DONE] Tasklet S04-F01-T01: Define The Registry Contract

Add one declarative registry for skills and commands. Record enabled or
disabled status, command exposure, and supported host surfaces. Include
disabled `git-write-escalation` without publishing it.

Validation: the registry declares every current skill and command source,
records host exposure, retains disabled `git-write-escalation`, and has no
benchmark entry.

### [DONE] Tasklet S04-F01-T02: Validate Registry Ownership

Add validation that rejects duplicate entries, missing enabled sources,
unregistered published surfaces, directory-driven activation, and
enabled-name collisions with declared project-local skills.

Validation: registry unit and CLI checks reject every named drift class,
and the core test command now runs the registry gate first.

## Feature F02: Generate Host Surfaces

### [DONE] Tasklet S04-F02-T01: Generate File-Based Commands

Generate supported file-based command adapters from the command registry
and canonical command sources. Remove hardcoded command inventories.

Validation: registry-driven generation and focused command tests prove all
five OpenCode adapters match their canonical TOML sources.

### [DONE] Tasklet S04-F02-T02: Generate Skill Packages

Generate OpenClaw and other copied skill packages from the skill registry
and canonical skill sources. Do not publish disabled or command-only
entries.

Validation: OpenClaw generation and focused tests cover every enabled
registry skill, reject unregistered directories, and omit disabled and
command-only entries.

### [DONE] Tasklet S04-F02-T03: Generate Runtime Registrations

Make JavaScript and Python host runtimes consume generated registry data
instead of maintaining independent skill and command lists. Preserve one
canonical parser and observable mode semantics.

Validation: generated-registry, Hermes, Pi, and runtime-source tests pass.
Hermes no longer scans directories and Pi has no auxiliary command list.

### [DONE] Tasklet S04-F02-T04: Generate Manifest Metadata

Generate repeated package, plugin, marketplace, ownership, and version
metadata from one source while preserving host-specific schema fields.

Validation: manifest generation and focused tests synchronize package,
plugin, marketplace, Hermes, and MCP metadata while retaining host fields.

## Feature F03: Install Codex And Project Skills

### [DONE] Tasklet S04-F03-T01: Add The Codex Installer

Adapt the project-agnostic `install-to-codex.sh` workflow to Ponytail.
Install enabled bundled skills, preserve existing non-empty global
instructions, and maintain an ownership manifest for managed links.

Validation: the parse-safe installer links every enabled registry skill and
the generated global policy, excludes disabled skills, preserves non-empty
global instructions, and records exact owned targets.

### [DONE] Tasklet S04-F03-T02: Bind Project-Local Skills

Support explicit repeatable project-local skill roots. Reject duplicate
owners and enabled bundled-skill name collisions. Never infer roots or
copy project-local skills into Ponytail.

Validation: explicit repeated project roots install by symlink; enabled-name
collisions and duplicate owners fail before any installation mutation.

### [DONE] Tasklet S04-F03-T03: Test Installer Lifecycle

Cover dry-run, check, idempotence, stale owned-link cleanup, repository
relocation, protected targets, project-local removal, and collisions.

Validation: the installer lifecycle script covers each named case and is part
of the core test command.
