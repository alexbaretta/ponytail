# Sprint S01: PostgreSQL Contract And Project Configuration

- Status: `DONE`
- Dependencies: Plan approval.

## Objective

Establish the stable PostgreSQL 18 contract, secure role boundary, and
project-owned non-secret configuration.

## Questions

- [RESOLVED] Journal functions sanitize and insert reporter data; reporters do
  not insert directly into the action table.
- [RESOLVED] `ponytail-journal.json` is the root-level committed JSON owner.
- [RESOLVED] The setup tool provisions the database and required roles from
  scratch when invoked through an authorized administrative connection.

## Feature F01: Project Configuration

Acceptance: a project has one committed UUIDv7 and validated non-secret
connection settings with documented PostgreSQL defaults and secret ownership.

### [DONE] Tasklet S01-F01-T01: Define Configuration Contract

Define the minimal `ponytail-journal.json` fields, defaults, parser behavior,
and error messages without sourcing executable project configuration.

Result: defined an exact V1 JSON reader with database, Unix-socket, Unix-role,
and external-password defaults in both setup and runtime paths.

### [DONE] Tasklet S01-F01-T02: Add Ponytail Configuration

Generate and commit Ponytail's project UUID and connection configuration, then
synchronize its documented ownership.

Result: added `ponytail-journal.json` with a committed UUIDv7 and registered its
V1 durable contract and project-structure ownership.

## Feature F02: Stable Journal Schema

Acceptance: the idempotent PostgreSQL 18 DDL establishes the stable relational
core, JSONB payload, reference data, constraints, indexes, functions, roles,
grants, and row-level security without altering an existing action table.

### [DONE] Tasklet S01-F02-T01: Define Reference Tables

Create the database and role provisioning contract, project and action-type
reference contracts, and idempotent seed behavior.

Result: setup now provisions the database and journal roles and reconciles
project and action-type reference rows.

### [DONE] Tasklet S01-F02-T02: Define Action Table

Create the immutable relational envelope, JSONB payload, UUIDv7 identities,
tasklet sequence uniqueness, open-action uniqueness, lifecycle checks, and
generated duration.

Result: added immutable `action_v1` with UUIDv7 identities, relational
constraints, generated duration, stable JSONB V1 payload, and required indexes.

### [DONE] Tasklet S01-F02-T03: Implement Journal Functions

Implement sanitized insertion, locked sequence allocation, start/transition,
heartbeat, completion, abnormal recovery, and prompt closure functions with
secure definer behavior.

Result: added secured start, heartbeat, and finish functions with sanitized
text, locked tasklet sequence allocation, exact transitions, and recovery.

### [DONE] Tasklet S01-F02-T04: Enforce Role Isolation

Implement reporter ownership, analyst visibility, super-journalist authority,
row-level security, and least-privilege grants.

Result: reporters use function-only writes and own-row reads, analysts read all
rows, and super-journalists retain repair authority.

### [DONE] Tasklet S01-F02-T05: Prove DDL Repeatability

Add focused PostgreSQL contract tests covering clean installation, repeated
installation, constraints, transitions, and role visibility.

Validation: `setup-project-journal.sh` completed twice against PostgreSQL 18.4
on a local Unix socket. `test-project-journal-postgres.sh` passed its
transactional reporter, analyst, immutability, and transition checks.
