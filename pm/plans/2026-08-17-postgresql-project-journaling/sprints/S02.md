# Sprint S02: CLI Lifecycle And Heartbeat

- Status: `DONE`
- Dependencies: S01.

## Objective

Add the parse-safe installed CLI that captures project, shell, Git, agent, and
command data while maintaining continuous action timing.

## Questions

No sprint-specific questions are currently open.

## Feature F01: Action Transitions

Acceptance: agents can start actions, cross action boundaries, span a prompt
across plans, close subagent work, and end a top-level reply with `over` while
providing only agent-owned fields.

### [DONE] Tasklet S02-F01-T01: Implement Configuration And Context Capture

Read validated project configuration and derive developer identity,
workstation, worktree, branch, commit, dirty status, client address, and JSONB
Git context without storing a diff.

Result: the CLI validates V1 JSON, applies PostgreSQL defaults, and captures
Git identity, workstation, worktree, branch, commit, dirty state, diff hash and
stat, and changed paths without storing the diff.

### [DONE] Tasklet S02-F01-T02: Implement Action Commands

Implement JSON-emitting start, transition, subagent completion, and `over`
commands with automatic prompt management and non-blocking failures.

Result: installed start and `over` commands now manage UUIDv7 prompts,
hierarchical agent state, exact database transitions, JSON output, and
top-level versus subagent completion.

### [DONE] Tasklet S02-F01-T03: Implement Wrapped Commands

Require one quoted Bash command, preserve environment-variable references in
storage, execute with the inherited environment, record process outcome, and
start `waiting_for_agent_action` automatically.

Result: `run_command` accepts exactly one quoted Bash command, records its
template and result, heartbeats while it runs, and transitions automatically
to `waiting_for_agent_action`.

## Feature F02: Local Heartbeat And Recovery

Acceptance: detached heartbeats provide one-second local and ten-second
database liveness while safe transitions and crash recovery retain the best
available end timestamp.

### [DONE] Tasklet S02-F02-T01: Implement Local State And Locking

Create ignored per-plan and hierarchical per-agent state, atomic locks, prompt
sharing, and safe heartbeat-process identity checks.

Result: ignored state is partitioned by plan and canonical agent hierarchy and
uses atomic writes plus a per-plan atomic lock.

### [DONE] Tasklet S02-F02-T02: Implement Heartbeat Lifecycle

Launch, refresh, stop, and verify detached heartbeat processes without
blocking the calling agent.

Result: each foreground journal process touches local state every second and
updates PostgreSQL every ten seconds while the agent tool runner remains free
to continue work; transitions terminate the preceding process gracefully.

### [DONE] Tasklet S02-F02-T03: Implement Abnormal Recovery

Recover missing heartbeat processes, stale prompt state, and unavailable local
state using the declared timestamp-source precedence.

Result: a forcibly killed heartbeat was recovered at its local last-touch
timestamp with `HEARTBEAT_LOST` and `LOCAL_HEARTBEAT` metadata.

### [DONE] Tasklet S02-F02-T04: Prove CLI Behavior

Add focused tests for parsing, JSON output, Git capture, quoted commands,
secret non-persistence, concurrency, subagents, heartbeats, recovery, and
journaling failures.

Validation: 18 focused CLI tests passed. Live PostgreSQL 18.4 tests proved
prompt reuse, tasklet sequences, one live heartbeat, automatic waiting,
abnormal recovery, subagent closure, ISO timestamps, and quoted-command secret
non-persistence. The stored template retained `$JOURNAL_TEST_SECRET` and did
not contain its environment value.

## Sprint Validation

Focused CLI tests and live installed-tool lifecycle validation passed against
the local PostgreSQL 18.4 Unix-socket database.
